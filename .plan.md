# School Management System — Implementation Plan

## Overview

Building a **complete School Management ERP** (17 modules) on top of the existing **Puroxa Water** Rails 8 + PostgreSQL + Tailwind + Devise application.

---

## Architecture

### Multi-Tenancy Strategy: Schema-based Isolation

Each `School` is a tenant. All school-related tables get a `school_id` column with database-level foreign keys + ActiveRecord `default_scope` or `acts_as_tenant` gem.

```
Super Admin (global scope, manages schools)
  └── School A (tenant scope, all school data tagged with school_id=1)
  └── School B (tenant scope, all school data tagged with school_id=2)
```

**Why this approach:**
- Simplest to implement in Rails
- Single database, no infrastructure changes
- PostgreSQL row-level security possible later
- Easy backup per school via `WHERE school_id = ?`

### User Model Extension

The existing `users` table gets `school_id` (nullable for Super Admin). Roles extended:

```ruby
ROLES = {
  super_admin: 0,   # Global: manages schools & billing
  school_admin: 1,  # Tenant: manages one school
  teacher: 2,       # Tenant: classes, attendance, homework
  parent: 3,        # Tenant: child progress, fees, chat
  student: 4,       # Tenant: learning portal, assignments
  staff: 5,         # Tenant: HR, library, transport
  # Keep existing:
  admin: 6, customer: 7, vendor: 8, subadmin: 9
}
```

Super Admin has `school_id = nil`. All school-scoped users have `school_id` set.

## Database Schema

### Core / Multi-Tenancy Tables

| Table | Purpose |
|---|---|
| `schools` | School name, address, logo, status (active/suspended), subscription_plan_id, subscription_expires_at |
| `branches` | Multiple branches per school (Main, City Campus) |
| `subscription_plans` | Plan name, price, features JSON, max_students, max_teachers |
| `school_subscriptions` | Join: school + plan + billing_cycle + payment_status |
| `academic_years` | 2025-26, 2026-27 — every school record tied to a year |
| `classes` | Grade/Class (Class 1, Class 2... Class 12) |
| `sections` | A, B, C per class |
| `class_sections` | Join: class + section + academic_year + class_teacher_id |
| `subjects` | Math, Science, English per school |
| `subject_teacher_assignments` | Which teacher teaches which subject to which class_section |
| `roles` / `user_roles` | If pivoting to role-based (optional, can extend existing enum) |

## Implementation Phases

### Phase 1: Foundation (Week 1)
**Goal:** Multi-tenancy + Core tables + Authentication + School Admin Dashboard

1. Add `acts_as_tenant` gem or custom tenant scope
2. Create core migrations: `schools`, `branches`, `academic_years`, `classes`, `sections`, `class_sections`, `subjects`
3. Extend `users` with `school_id`, new roles
4. Super Admin: CRUD schools, manage subscriptions
5. School Admin: Dashboard, branch management, staff invite
6. Layouts: Super Admin layout, School Admin layout, Teacher layout, Parent layout, Student layout
7. Seeds: 1 super admin, 1 sample school with branches

### Phase 2: SIS + Admission + Attendance (Week 2)
**Goal:** Student life cycle from admission to attendance

1. Online admission form (public) + document upload (Active Storage)
2. Admission workflow (Applied → Under Review → Approved → Rejected)
3. Auto Student ID + Roll Number generation
4. Student Profile (personal, parent link, documents, medical)
5. Digital ID Card with QR code (`rqrcode` gem)
6. Daily attendance + Period-wise attendance
7. Teacher attendance

### Phase 3: Fee + Exam + Homework (Week 3)
**Goal:** Financial + Academic management

1. Fee categories & structures per class
2. Fee assignment to students
3. Online payment integration (Razorpay/Stripe)
4. Partial payments, late fees
5. Exam types, exam creation, scheduling
6. Grading system (school-configurable)
7. Mark entry by teachers
8. Auto result generation + Report Card PDF (`wicked_pdf` or `grover`)
9. Class ranking
10. Homework create → submit → grade flow

### Phase 4: LMS + Live Classes + Communication (Week 4)
**Goal:** Digital learning + engagement

1. Courses → Chapters → Topics hierarchy
2. Learning content upload (PDF, video embed)
3. Quiz creation (MCQ, Short, Long)
4. Student quiz attempts + auto-scoring
5. Progress tracking (% completion)
6. Live Class scheduling (Zoom/Google Meet URL storage)
7. Recording links
8. Announcements (role-targeted, class-targeted)
9. Internal chat (Teacher↔Parent, Teacher↔Student)
10. Notification system (in-app)

### Phase 5: Library + Transport + Hostel (Week 5)
**Goal:** Physical facility management

1. Book catalog, barcode support
2. Issue / Return / Fine calculation
3. Vehicles, Drivers, Routes
4. Route stops & timing
5. Student transport allocation
6. Hostel → Room → Bed allocation
7. Hostel fee link to fee management

### Phase 6: HR/Payroll + Inventory + AI (Week 6)
**Goal:** Operations + AI differentiation

1. Employee profiles, departments, designations
2. Leave types + application + approval workflow
3. Payroll run → Salary slip generation
4. Asset tracking + maintenance logs
5. Stock management
6. **AI Report Generator** — OpenAI API integration: teacher notes → full report
7. **AI Question Paper Generator** — topic + difficulty → MCQ/Short/Long
8. **AI Homework Generator** — class + subject → auto homework
9. **AI Parent Chatbot** — RAG-based or simple prompt-based Q&A

### Phase 7: Analytics + Polish (Week 7)
**Goal:** Dashboards, charts, testing, deployment prep

1. Admin Dashboard: Total Students, Revenue, Attendance % (Chart.js)
2. Teacher Dashboard: Class Performance
3. Parent Dashboard: Child Progress
4. Student Dashboard: Upcoming classes, pending homework
5. SMS integration (Twilio/Fast2SMS)
6. Email (Action Mailer)
7. Push notifications (OneSignal or web push)
8. Full testing + bug fixes
